# Adversarial security review: Generated Dialogue Subtitles (pre-implementation baseline)

Review scope: falsify the proposed **profile-local BYOK**, **native provider identity**, **grant**, and **PCM** boundaries for the Generate-dialogue-captions (beta) mission against the code as it exists today. Repo state: `6e225905` (docs-only commits on top of research baseline `eca648a8`), working tree clean. The reviewed docs are `docs/ai-media-research/decision.md`, `docs/agent-briefs/generated-dialogue-subtitles-hammersmith.md`, `docs/ai-media-research/lanes/07-byok-security-tv-ux.md`, and `docs/ai-media-research/audits/security-ux-feasibility-audit.md`. Every finding below was verified against current source; this review changed no repository files.

## Summary

The profile-local BYOK, native provider identity, grant and PCM boundaries as specified are **falsified in their strong form**: none of them exists in code, and each one has at least one structural property of the current app that actively contradicts it rather than merely not supporting it yet.

- **Credential store:** there is no broker and no AAD binding anywhere. Every credential except Simkl is plaintext at rest; a `.preferences_pb.bak` shadow-copy mechanism duplicates every plaintext store and survives both profile deletion and global cleanup; and profile identity is a recycled numeric ID with no generation or UUID. "Profile-local" today would mean "plaintext in a file that outlives the profile and attaches to the profile ID's next owner."
- **Network:** the unqualified DI client — the one a new provider adapter would inherit unless it builds its own — is trust-all (accepts every certificate and hostname). It already carries live MDBList API keys in URLs. The DEX plugin client (`ignoreAllSSLErrors()`) is worse. The global cleartext opt-in means even "HTTPS" is not structurally enforced.
- **Identity/grants:** application ID does not identify trust. The plugin flavor `com.nuvio.tv` is a package name that sideloaded APKs can also declare; the `full` flavor ships both a QuickJS runtime that gets arbitrary settings plus the compiled TMDB key plus an unrestricted fetch bridge, and a same-process `DexClassLoader` path with the app classloader as parent and app context handed to plugin code. There is no signing-digest check, no process isolation, and no consumer authentication, so a bearer grant handle and "fail closed on DEX" are both unverifiable claims in the current process model.
- **PCM:** the only audio processors attached to the sink are `GainAudioProcessor` (gain only, no PTS) and `DefaultAudioSink`'s Sonic speed changer. `PlaybackSpeedAwareAudioRenderer.supportsFormat` returns `FORMAT_HANDLED` for passthrough-capable DRM formats with `TUNNELING_SUPPORTED`, so decrypted-PCM capture is not even guaranteed for clear content. Seeks from the coordinator-required paths are unsynchronized with any epoch (audio-track switch and 416 recovery even rewind ~1 ms), player failover rebuilds the whole Exo instance, and `onAudioTrackPositionDiscontinuity` is unimplemented. The "audio_thread never blocks, bounded memory, epoch-clean" boundary is buildable at this seam but is entirely unbuilt and currently unenforceable.
- **Telemetry/LAN:** Sentry is on by default, its `beforeSend` clears only `request`/`user` while breadcrumbs carry raw `error_message` (240 chars) and encoded paths; `urlForLog`/`rawForLog`/`bodySnippetForLog` are identity functions; the account screen logs raw device codes, user codes and verification URLs; the QuickJS runtime logs request bodies and 300-char response previews; and both NanoHTTPD servers are unauthenticated plain-HTTP LAN endpoints returning full state and applying writes with no token, Origin check or session.
- **Custody:** the sync layer's whole design pattern is "serialize credentials to JSON and push them to the server." A profile-local no-sync BYOK can be honored only by omitting the AI provider from that architecture, not by participating in it.
- **DRM:** there is no DRM session manager anywhere, yet `PlaybackSpeedAwareAudioRenderer.supportsFormat` reports DRM passthrough formats as `FORMAT_HANDLED` with tunneling support. "Known encrypted fixtures send zero bytes" is enforceable only via a pre-upload veto the app does not have, plus the brief's own explicit preflight list.

What is genuinely **deferred infrastructure, not a release blocker** (falsifying the "more is required" direction too): migrating debrid/MDBList/Trakt credentials into the vault, credential-type redaction across all legacy stores, blocking the unauthenticated LAN servers or building the E2EE LAN import flow, the API-37/`ACCESS_LOCAL_NETWORK` permission state machine, Supabase SDK storage investigation, household/admin/child roles (which cannot exist — `UserProfile` has no role field), custodial/E2EE sync, per-plugin QuickJS grant evaluation, isolated DEX runner, durable jobs, and certificate pinning beyond platform trust. Removing trust-all TLS from the legacy clients and banning secret-shaped addon URLs are also **not** BYOK prerequisites; the blocker is only that the AI adapter must not inherit them.

Release blockers and executable controls are listed under **Required launch controls** at the end.

Finding: BYOK credential store does not exist, and "profile-local" is unimplementable on current profile identity: numeric IDs are recycled with no UUID/generation, while every non-Simkl credential sits in plaintext Preferences DataStore and every store gains an unencrypted `.preferences_pb.bak` shadow copy that survives profile deletion and sign-out.
Evidence: `rg -n "byok|CredentialBroker|MediaTransformProvider|GrantStore" app/src` returns nothing (no vault, no AAD types). `ProfileManager.createProfile` (`app/src/main/java/com/nuvio/tv/core/profile/ProfileManager.kt:84-101`) picks `(2..MAX_PROFILES).firstOrNull { it !in usedIds }` — a freed ID is immediately reusable — and `deleteProfileDataAsync` (lines 113-127) deletes only files ending exactly `_p<id>.preferences_pb`, never `_p<id>.preferences_pb.bak`. `ProfileDataStoreFactory.clearProfileScopedData` (lines 87-105) deletes only names ending exactly `.preferences_pb`, and the deletion search at `ProfileManager.kt:105-132` likewise misses `.bak`. `writeShadowCopy` (lines 178-190) copies every store to `.bak` after each edit. `DebridSettingsDataStore.kt:42-45` stores torbox/premiumize/real-debrid keys as plain `stringPreferencesKey`; `TraktAuthDataStore.kt:29-44` stores access/refresh tokens and device codes the same way. The only Keystore pattern, `AndroidSimklAuthStorage.kt:230-260`, uses AES-GCM with a random IV but no AAD — ciphertext can be swapped between profiles or records without failing authentication.
Impact: A profile-local AI key stored the way all current credentials are stored would be (a) plaintext on disk twice, (b) readable by any same-process plugin code, and (c) silently inherited by the next profile created with the same numeric ID after deletion, or readable by anyone extracting the surviving `.bak`. The central "profile-local BYOK" claim is false under the current storage and identity model.
Fix: Before any BYOK code ships: add an immutable per-profile generation/UUID to `UserProfile`/`ProfileDataStore` and bind it into AAD (`nuvio-byok-v1|applicationId|installId|PROFILE|profileUuid|provider|credentialId`) so swapped ciphertexts fail GCM; build the broker as a separate module with one Keystore master alias, metadata-only persistence, and no plaintext getter; register it in `ProfileScopedCredentialStore` and in both deletion paths; make `.bak` cleanup part of profile deletion (extend the suffix match) with a deletion test asserting no `.bak` survives ID reuse. Do NOT put AI credentials in Preferences DataStore at all.

Migrating the legacy trust-all clients and the global cleartext opt-in off trust-all is NOT a launch blocker for this mission — only isolation of the AI client is.

Finding: No provider identity exists, and application ID does not create one: the `full` flavor's `applicationId = "com.nuvio.tv"` is a package name any sideloaded APK can also declare, and that same flavor ships both the QuickJS runtime and a same-process `DexClassLoader` path with the app classloader as parent — so "native in both intended distribution flavors" cannot distinguish first-party from attacker code.
Evidence: `app/build.gradle.kts:198-219`: flavor `full` has `applicationId = "com.nuvio.tv"` and `FEATURE_PLUGINS_ENABLED = "true"`; flavor `playstore` has `applicationId = "com.nuvio.app"` and plugins disabled. `ExternalExtensionLoader.kt:276-281` (`app/src/full`) constructs `DexClassLoader(dexFile.absolutePath, codeCacheDir.absolutePath, null, context.classLoader)` — the app classloader as parent — then (lines ~310-330) hands the plugin `AcraApplication.getActivity() ?: context` and calls `plugin.load(context)`; `classLoaderCache` retains the loader for the process lifetime. `PluginRuntime.kt:448-452,676-683` (`app/src/full`) injects the full `scraperSettings` map (`__get_scraper_settings`) and the compiled TMDB key (`__get_tmdb_api_key`) into every QuickJS instance, and `performNativeFetch` (lines ~506-600) executes arbitrary caller-chosen URL/method/headers/body with a default desktop User-Agent. No `PackageManager` signature/digest comparison exists anywhere (`rg -n "signingInfo|GET_SIGNATURES|signatures" app/src` is empty).
Impact: A malicious DEX extension runs with the app UID, can read the app-private vault file and SharedPreferences, reflect into broker classes, hook OkHttp after decryption, and exfiltrate through its own network stack; QuickJS receives whatever the host injects and an unrestricted fetch bridge. "Signing-digest identity", "fail closed if external DEX can execute in the credential-holding process" (brief), and even the audit's `UNSUPPORTED_UNTRUSTED_RUNTIME` response are unverifiable inside this process: there is no runtime signal that could reliably detect the DEX, and a return code does not remove the DEX's ability to observe the key.
Fix: First public beta: keep BYOK first-party in-process and put the provider adapter in `src/main` (it already must be, per the brief) with zero exposure to `SCRAPER_SETTINGS`, plugin console output, or the fetch bridge; exclude both QuickJS operations and DEX from grant eligibility (`ConsumerType.FIRST_PARTY` only) until isolation exists. A verified signer check (`packageManager.getPackageInfo(pkg, GET_SIGNING_CERTIFICATES)` digest pinned against `BuildConfig`) must gate any future bound-service provider. Isolated-process DEX runner, per-plugin QuickJS grants, and any Binder/AIDL provider protocol are deferred post-beta work.

Finding: Grant machinery does not exist, and the specified GrantHandle is a bearer capability by construction — a copied string must authorize `execute` unless the broker independently authenticates callers, which nothing in the current process can do.
Evidence: No `MediaCapabilityGrantStore`, `GrantHandle`, or revocation code exists (`rg` over `app/src` is empty). The lane's own contract (`07-byok-security-tv-ux.md:132-168`) defines `GrantHandle` as "random, opaque, non-secret" and `execute(handle, request)` as the only operation surface — possession of the string is the authorization. There is no caller authentication primitive in-process: QuickJS plugins share the same heap and the DEX path shares the classloader (Finding above).
Impact: Any code that obtains the handle string (logged, leaked via `toString`, read from a compromised runtime) can spend the user's provider money until expiry; a "fail closed on wrong signer" check has no signer to check. The grant boundary as specified is security theater in the current trust model.
Fix: For the beta, do not issue grant strings at all: one first-party adapter calls the broker directly with the profile generation check inside every operation (mirror `AndroidSimklAuthStorage.mutate(scope)` + `requireCurrentScope` pattern from `ProviderCredentialSyncService.kt:84-88`), short-lived per-session expiry, revoked by the session coordinator on every identity change. If/when handles are introduced, bind them to consumer identity + profile generation + expiry, treat them as sensitive (constant `toString`, never logged), and re-verify inside `execute`.
Priority: P0
Confidence: high

Finding: The PCM boundary is currently zero: no capture processor exists, the only sink processors are gain and Sonic, decrypted-PCM delivery is not guaranteed (passthrough/tunneling preferred for AC3/DTS/TrueHD, and DRM formats are reported FORMAT_HANDLED with tunneling support), and every coordinator-required lifecycle event either lacks a hook or actively contaminates epoch ordering.
Evidence: `PlayerRuntimeControllerInitialization.kt:2086` attaches exactly `.setAudioProcessors(arrayOf(gainAudioProcessor))` to `DefaultAudioSink`; `GainAudioProcessor.kt` is pure gain (no PTS, no tap); Sonic is added by `DefaultAudioSink` only for speed != 1x. `PlaybackSpeedAwareAudioRenderer.supportsFormat` (lines 46-56) returns `RendererCapabilities.create(C.FORMAT_HANDLED, ADAPTIVE_NOT_SEAMLESS, TUNNELING_SUPPORTED, ...)` when `supportsFormatDrm(format)` and passthrough is possible — i.e. DRM audio can be selected for passthrough, and on a passthrough route no decoded PCM reaches any processor. `shouldUseBypass` is overridden to refuse bypass only when `shouldForcePcmForFormat` (line 131+). Coordinator-required hooks: `selectAudioTrack` (`PlayerRuntimeControllerTrackSelection.kt:44-82`) applies a `TrackSelectionOverride` then `player.seekTo((pos - 1))` — a ~1 ms rewind and no epoch; `retryCurrentStreamAfter416`/timeout/NPE/crash recovery (`PlayerRuntimeControllerObservers.kt:666-706`) all call `scheduleDeferredPlayerReinitialize`, which rebuilds the ExoPlayer instance (`releasePlayer` nulls `playbackSpeedAwareAudioSink`, `PlayerRuntimeControllerLifecycle.kt:105`); `onAudioTrackPositionDiscontinuity` is not implemented anywhere (`rg` empty); `releasePlayer` cancels ~20 jobs by hand with no registry a coordinator could join.
Impact: As specified, "receives normalized selected-track PCM with media-time anchors, generation and seek epoch" has no seam to attach to: passthrough sessions would deliver silence-or-nothing to a tap, track switches and micro-rewinds would emit out-of-order frames with no epoch to reject them, and every failover rebuilds the sink mid-generation. The boundary is buildable at this seam (the sink wrapper and renderer override prove the team can force PCM), but today it is falsified in both directions — no capture exists AND the capture policy (force-PCM transition, truthful restore, epoch increments) has no enforcement points.
Fix: Add a dedicated `PcmTapAudioProcessor` (not modifications to `GainAudioProcessor`) copying into a fixed-capacity non-blocking queue; a `PcmRoutePolicy` that refuses generation (visible state, not silent fallback) when `shouldForcePcmForFormat`/passthrough/tunneling/offload is active, and restores route state on stop; a single `MediaTransformSessionCoordinator` called from `selectAudioTrack`, every `retryCurrentStream*`, `releasePlayer`, MPV switch (`PlayerRuntimeControllerMpv.kt:83-87` releases Exo), episode change and profile switch, incrementing epoch BEFORE the first post-change sample; pair sample counts with `onAudioTaskEnded`/renderer timestamps, not `queueInput` wall time. Bounded-queue and zero-post-revoke behavior must be unit-tested on the real sink pipeline.

## Required launch controls

Release blockers (must be demonstrably green before any public-capable beta):
1. Dedicated provider network client with platform TLS/hostname validation; the AI adapter cannot obtain the unqualified or CloudStream clients. Executable: MITM test with an untrusted CA + hostname mismatch fails every provider call (instrumentation, or Robolectric + MockWebBroker TLS handshake test against the `@Named` client); static DI-graph test asserting no provider Retrofit/engine consumes `provideOkHttpClient`.
2. Profile-local encrypted credential vault with AAD bound to installation + profile UUID/generation + provider + record ID; no plaintext DataStore/SavedState/backup value; no plaintext getter. Executable: JVM unit tests — two encryptions differ; ciphertext swapped across install/profile/provider/record fails GCM; alias missing/invalidated fails closed; binary/string scan of DataStore, `.bak`, cache, SavedState, work data, notifications and support exports finds no canary key.
3. Immutable profile generation/UUID in every in-flight operation and in deletion. Executable: profile switch during test/inference rejects the response; delete profile → create profile with same numeric ID → assert zero credential/grant/cache residue (including `.preferences_pb.bak`) before the ID is reusable.
4. BYOK unavailable to plugins in both directions: no DEX/QuickJS consumer receives keys, handles, auth headers or selected-source URLs/headers/PCM; feature works without any plugin runtime (playstore flavor) and is grant-less toward plugin code in the full flavor. Executable: fake provider e2e in `playstore` build; source-level test that provider code has no dependency on `src/full` classes; canary test that `SCRAPER_SETTINGS`/`__get_tmdb_api_key` injection surfaces never receive AI values.
5. Telemetry off for AI paths or canary-proven redaction. Executable: with a canary in URL path/query, headers, bodies, plugin console, provider response and nested exception causes — release Logcat and the server-side stored Sentry event contain zero canary occurrences; otherwise Sentry stays off for the beta and the disclosure strings are corrected.
6. No credential endpoint on NanoHTTPD servers and no AI state on LAN. Executable: unauthenticated GET against `AddonConfigServer`/`DebridFormatterConfigServer` route tables returns no AI provider/profile/grant/key data (route-table unit test + device GET sweep).
7. PCM tap and session coordinator with epoch semantics. Executable: audio-thread unit test proving no blocking/Binder/network on the capture path and bounded queue under slow-consumer pressure; zero frames delivered after revoke (pause/stop/seek/profile switch/audio-track change/episode change/release); old-generation/epoch callbacks rejected; passthrough/offload/tunneling session refuses generation (truthful state) and route state restores after stop; seek at 5/30/60 min shows no old-epoch contamination.
8. DRM veto before paid work. Executable: known encrypted HLS/DASH fixtures produce zero provider calls and zero payload bytes; license URLs, cookies, debrid headers and playback Authorization never leave acquisition (network-recording fake provider asserts request contents).
9. Explicit user start with consent copy naming provider, active profile, what leaves the TV, billing owner and hard cap; missing subtitles never auto-start capture. Executable: UI test asserting no capture session is created without the explicit Start action; hard job cap checked before every new request/shard (unit test with fake provider counting calls past cap).
10. No AI entry in credential sync and no AI key in URLs. Executable: `ProviderCredentialSyncService.currentSnapshot()` contains no AI providers (unit test on the provider set); URL-canary test inserting the key into path/query/userinfo/fragment/redirect of every outgoing provider request fails closed.

### Deferred infrastructure (explicitly not launch controls — do not gate the beta on these)

Migration of debrid/MDBList/AnimeSkip/Trakt credentials into the vault; removing trust-all TLS from the legacy unqualified/Trakt/CloudStream clients; global cleartext opt-in removal; addon secret-bearing-URL redaction/quarantine; E2EE cross-device sync and custodial modes; Supabase session-storage and backend RPC/RLS verification; isolated-process DEX runner and per-plugin QuickJS grants; household/admin/child roles (no role model exists in `UserProfile`); LAN server hardening and API-37 `ACCESS_LOCAL_NETWORK` state machine (target is 36); offline LAN key import; durable background jobs/foreground service; certificate pinning beyond platform trust; MPV live capture (export-only reuse until a tested native seam exists).
