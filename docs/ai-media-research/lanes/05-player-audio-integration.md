# Lane 05 — Nuvio player audio integration

**Research baseline:** repository commit `eca648a86de8021a47299549d6dedbf0420b7188` (29 August 2026). That commit itself only adds offscreen compositing to two home-screen gradients and does not modify player/audio code (`app/src/main/java/com/nuvio/tv/ui/components/HeroCarousel.kt:419-425`, `app/src/main/java/com/nuvio/tv/ui/screens/home/ClassicFocusGradientBackdrop.kt:96-102`). The findings below trace the complete tree at that commit. Nuvio declares Media3 1.8.0-era local/forked AARs plus stock adaptive modules and `mpv-android-lib:0.1.12`; this is not a stock, uniformly versioned Media3 deployment (`app/build.gradle.kts:348-355`, `app/build.gradle.kts:452-478`, `app/build.gradle.kts:496`). Current upstream verification used official Android Media3 1.11.0 documentation/source and the current official mpv manual/source.

## Executive summary

Nuvio already has most of the player-control seams needed for near-real-time dubbing—central URL/header normalization, engine-specific track enumeration and selection, live delay, seek/speed routing, failover, and teardown—but it has **no external-audio data model or player path**. The lowest-risk MVP is an **MPV-only `audio-add` path** for a completed or append-readable progressive audio asset, surfaced as a normal `AudioSelectionOverlay` track and explicitly marked experimental; Media3 `MergingMediaSource` should be the second path only for finalized, seekable, single-period sidecars with carefully filtered primary video and independent headers. The robust architecture is a localhost session proxy that publishes synchronized audio as standards-native HLS/DASH (or remuxes a progressive source), owns a media-time mapping and bounded correction loop, and gives both engines one URL; it is substantially safer for seeks, partial availability, headers, failover, and memory/network accounting than trying to inject growing segments independently into both engines.

## Key findings

### 1. Selected `Stream` reaches the player as one primary URL plus one request-header map; there is nowhere to carry dubbed audio

**What.** A `Stream` can carry URL/torrent/external metadata and `behaviorHints.proxyHeaders`, but no auxiliary audio URI, audio headers, language, duration, origin timestamp, DRM configuration, or availability state (`app/src/main/java/com/nuvio/tv/domain/model/Stream.kt:10-27`, `app/src/main/java/com/nuvio/tv/domain/model/Stream.kt:182-190`). `getStreamUrl()` prefers a non-magnet/non-torrent `url` or `externalUrl`; torrent detection only wins when no HTTP URL is present (`app/src/main/java/com/nuvio/tv/domain/model/Stream.kt:32-52`). Stream selection builds `StreamPlaybackInfo` using only `proxyHeaders.request` (`app/src/main/java/com/nuvio/tv/ui/screens/stream/StreamScreenViewModel.kt:1302-1335`, `app/src/main/java/com/nuvio/tv/ui/screens/stream/StreamScreenViewModel.kt:1820-1854`), navigation JSON-encodes that map and the primary URL (`app/src/main/java/com/nuvio/tv/ui/navigation/Screen.kt:70-133`), and `PlayerNavigationArgs` decodes the same fields (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerNavigationArgs.kt:8-38`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerNavigationArgs.kt:50-99`). Both manual and autoplay navigation pass only these primary fields (`app/src/main/java/com/nuvio/tv/ui/navigation/NuvioNavHost.kt:538-615`).

**Evidence.** On controller construction, the URL and headers are normalized, URL userinfo is converted to Basic Authorization, blank/`Range` entries are removed, and one `currentStreamUrl/currentHeaders` pair becomes runtime truth (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeController.kt:187-224`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:322-354`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:674-728`).

**So what.** Add a first-class immutable `AuxiliaryAudioDescriptor` at the resolved playback boundary, not ad-hoc query parameters. Minimum fields: stable ID, session ID/generation, URI, per-audio headers, MIME/container hint, language/label, `originMediaTimeMs`, producer-complete/live flag, seekable flag, available interval(s), expected duration, DRM descriptor, and transport mode. Do not inherit primary headers blindly: debrid Authorization/Cookie/Host frequently must not reach an unrelated dubbing host.

### 2. Existing Media3 construction is an excellent seam, but currently creates exactly one source and wraps it for delay

**What.** `PlayerMediaSourceFactory.createMediaSource` sanitizes primary headers, builds a per-source `DataSource.Factory`, infers HLS/DASH/progressive type, creates a `MediaItem`, chooses HLS/DASH/default progressive, and finally wraps the result in `AudioDelayMediaSource` (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:80-116`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:118-195`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:643-655`). HLS/DASH skip the progressive parallel-range and VOD disk-cache path; progressive HTTP may use a custom chunk session, and disk cache is gated away from HLS/DASH (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:116-173`). The player builds custom renderers/track selector, calls this factory, then `setMediaSource`, resume-seeks, holds `playWhenReady=false`, and starts only after first video frame so startup audio does not race video (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:894-928`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:943-1018`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:1284-1305`).

**Evidence.** Official Media3 says `MergingMediaSource` plays sources in parallel and recommends `adjustPeriodTimeOffsets=true` and `clipDurations=true` in almost all cases ([Media sources](https://developer.android.com/media/media3/exoplayer/media-sources#advanced_media_source_composition)). Current upstream source still requires equal period counts and prefixes merged track/format IDs (`MergingMediaSource.java:48-54` at [Media3 1.11.0 source](https://github.com/androidx/media/blob/1.11.0/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/source/MergingMediaSource.java)); it creates every child period at a time-offset-adjusted start and optionally clips the aggregate (`MergingMediaSource.java:217-246`). It waits for every child timeline before publishing the merged timeline, computes offsets only from each period's `positionInWindow`, and clips each period to the shortest known adjusted duration (`MergingMediaSource.java:286-317`, `MergingMediaSource.java:331-361`).

**So what.** The Media3 implementation seam should be a new `createPlaybackMediaSource(primary, auxiliaryAudio?)` immediately before the existing delay wrapper. Build primary and audio with **separate** data-source factories/header maps. Filter the primary to video/text (or at minimum disable/select around its embedded audio) and expose sidecar audio as a separate group. Apply the existing `AudioDelayMediaSource` only once around the final composite; otherwise offsets become ambiguous. Because Nuvio ships forked AARs, compile and run contract tests against the actual binary before assuming 1.11.0 APIs/bug fixes are present.

### 3. `MergingMediaSource` is viable only for a constrained finalized-sidecar MVP, not arbitrary growing dubbing audio

**What.** A normal progressive video and progressive audio sidecar are often each one period, so merge can work. But timeline alignment is structural, not semantic: `adjustPeriodTimeOffsets` aligns period positions-in-window, not speech/content landmarks. If the generated audio starts 1.4 seconds after the source dialogue but both files start at PTS zero, merging does not discover or repair that offset. `clipDurations=true` ends playback at the shortest known source; that is unacceptable when audio is partial/growing. `clipDurations=false` preserves primary duration, but the selected audio can hit EOS and leave silence while video continues.

**Evidence.** Upstream `MergingMediaPeriod` prepares every child before becoming prepared (`MergingMediaPeriod.java:87-99`), combines every child track group (`MergingMediaPeriod.java:306-339`), and fails if children enable at different positions (`MergingMediaPeriod.java:114-181`). On discontinuity and seek it requires every enabled period to land on the same position or throws `IllegalStateException` (`MergingMediaPeriod.java:235-275`, [Media3 1.11.0 source](https://github.com/androidx/media/blob/1.11.0/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/source/MergingMediaPeriod.java)). The official tests confirm shortest-duration clipping, unknown-duration handling, period-count failure, offset-adjusted samples, and child cleanup (`MergingMediaSourceTest.java:48-107`, `MergingMediaPeriodTest.java:108-165` at the corresponding [Media3 source tree](https://github.com/androidx/media/tree/1.11.0/libraries/exoplayer/src/test/java/androidx/media3/exoplayer/source)).

**So what.** Gate direct merge to: VOD, finalized audio, seekable input, known compatible duration, equal period topology (practically one period), clear or explicitly compatible DRM, and a verified media-time origin. Do not use shortest clipping for a partial dub. A static silence-padding source can represent a positive initial gap, but a continuously growing progressive file remains difficult: stale Content-Length/EOS, extractor index availability, and child seek exactness can still break it. Replacing the composite when audio advances discards buffers and can interact badly with Nuvio's existing source-rebuild/recovery logic.

### 4. Standards-native HLS/DASH alternate audio is the best direct Media3 transport and the best cross-engine contract

**What.** If the producer can publish a proper HLS master with audio renditions or DASH MPD with an audio AdaptationSet on the same timeline, the existing source factory and track UI naturally discover/select them—no app-side `MergingMediaSource` is needed. Official Media3 automatically exposes manifest tracks; its track API groups different audio languages separately and allows runtime `TrackSelectionOverride` ([Track selection](https://developer.android.com/media/media3/exoplayer/track-selection#querying_the_available_tracks), [specific tracks](https://developer.android.com/media/media3/exoplayer/track-selection#selecting_specific_tracks)). DASH requires demuxed video/audio/text AdaptationSets and supports multi-period playback ([DASH](https://developer.android.com/media/media3/exoplayer/dash)); official HLS guidance prefers demuxed streams and complete multivariant-playlist metadata ([HLS](https://developer.android.com/media/media3/exoplayer/hls#creating_high_quality_hls_content)).

**Evidence.** Nuvio already enumerates every Media3 audio group/format into `TrackInfo` and records selection (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTracks.kt:24-35`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTracks.kt:96-137`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTracks.kt:291-319`); selection creates a type override and nudges one millisecond backward to escape segment-switch buffering (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTrackSelection.kt:44-80`). Nuvio's HLS factory enables chunkless preparation (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:184-190`), so rendition metadata/codecs must be in the master; official docs warn missing declarations can hide tracks until chunkless preparation is disabled, at startup-cost ([HLS customization](https://developer.android.com/media/media3/exoplayer/hls#disabling_chunkless_preparation)).

**So what.** For robust near-real-time output, publish a localhost HLS master/MPD where original video is proxied/remuxed and dubbed audio is segmented on the same media-time grid. Use independent, monotonically increasing sequence numbers/timestamps, atomic manifests, no rewriting already advertised segments, and an explicit discontinuity/new period only when correction cannot be absorbed. Segment boundaries around 250–1000 ms trade latency against request/decoder overhead; validate TV hardware with fMP4 AAC first. `MergingMediaSource` remains a finalized-file fallback, not the primary live protocol.

### 5. MPV already has all upstream primitives for external audio, but Nuvio's wrapper does not expose them

**What.** Nuvio MPV currently applies headers, `loadfile`s one URL, resets `aid/sid` to auto, reads `track-list`, selects by `aid`, and applies `audio-delay`, seek (`time-pos`) and speed (`speed`) (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:35-123`, `app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:145-210`, `app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:251-267`, `app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:500-580`). It has only `sub-add`; there is no `audio-add`, `audio-remove`, `audio-reload`, `audio-file`, or sidecar-header API (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:444-481`).

**Evidence.** The official mpv command is `audio-add <url> [flags [title [lang]]]`, with `select`, `auto`, and `cached` behavior inherited from `sub-add`; `audio-remove` and `audio-reload` are also available ([mpv manual — Track Manipulation](https://mpv.io/manual/stable/#track-manipulation)). `--audio-files` plays external audio while viewing video ([mpv manual — Audio](https://mpv.io/manual/stable/#audio)); `track-list/N/external`, `/external-filename`, and `/selected` identify it ([mpv manual — track-list](https://mpv.io/manual/stable/#command-interface-track-list)). Positive `audio-delay` delays audio and negative values delay video; speed changes default to pitch-preserving `scaletempo2` ([mpv manual — audio-delay](https://mpv.io/manual/stable/#options-audio-delay), [speed](https://mpv.io/manual/stable/#options-speed)).

**So what.** The concrete MPV MVP is small: add `addExternalAudio(url,title,lang,headers): result`, invoke `audio-add ... select`, wait until an external audio track appears, select its ID, then refresh Nuvio's normal `audioTracks`. Add remove/reload and generation checks. However, Nuvio currently sets global `http-header-fields`; loading a sidecar with different auth would either fail or risk sending primary credentials to the audio host (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:656-682`). Prefer a localhost URL needing no upstream credentials, or use per-file options only after verifying the wrapper/mpv version supports safe property scoping. Never concatenate untrusted headers without CR/LF rejection.

### 6. Existing runtime delay is immediately reusable, but it is manual phase correction—not drift correction

**What.** The Audio overlay already combines track choice and audio controls. Delay is adjustable from -3000 to +3000 ms in 25 ms steps (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerPlaybackEvents.kt:25-45`, `app/src/main/java/com/nuvio/tv/ui/screens/player/AudioSelectionOverlay.kt:371-500`) and is optionally persisted per detected output route (`app/src/main/java/com/nuvio/tv/data/local/AudioDelayRouteDataStore.kt:10-37`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerAudioDelayRoutes.kt:63-87`). MPV receives `audio-delay` directly (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerPlaybackEvents.kt:36-48`). Media3 uses an unusual wrapper that shifts **video** sample timestamps opposite the requested audio delay, because audio is normally the master clock; subtitle rendering also includes the audio offset (`app/src/main/java/com/nuvio/tv/ui/screens/player/AudioDelayMediaSource.kt:70-103`, `app/src/main/java/com/nuvio/tv/ui/screens/player/AudioDelayMediaSource.kt:148-169`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:2313-2324`).

**Evidence.** The wrapper consults an atomic provider at sample read/skip time, so an update is live and does not rebuild the source (`app/src/main/java/com/nuvio/tv/ui/screens/player/AudioDelayMediaSource.kt:145-170`). Seek methods themselves pass through unchanged (`app/src/main/java/com/nuvio/tv/ui/screens/player/AudioDelayMediaSource.kt:113-130`). MPV delay is re-applied after resume seeks, user seeks, and audio-output reload (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerMpv.kt:473-478`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerMpv.kt:521-533`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerAudioDelayRoutes.kt:239-248`).

**So what.** Reuse this UI and control for user calibration, but split delay into `routeDelayMs + dubBaseOffsetMs + runtimeCorrectionMs`, display the effective value, and persist only the user/route component. A constant delay cannot fix clock-rate mismatch: 100 ppm drift becomes 360 ms/hour. For robust dubbing, estimate error `e = audioMediaTime - (videoMediaTime + targetOffset)` from producer timestamps and apply: (1) bounded audio tempo correction (for example ±0.5–1%) when `|e|` is modest, (2) a short crossfaded insert/drop or sidecar re-seek at a threshold, and (3) a hard resync after seek/discontinuity. Do not oscillate Nuvio's Media3 video-timestamp delay every polling tick; that changes the master-side presentation timeline and can stutter. Keep fine correction in the generated audio/proxy where possible, reserving player delay for a slow, coarse phase adjustment.

### 7. Seeks and speed are centralized, so a dubbing session can observe one authoritative command stream

**What.** Nuvio routes preview/commit/absolute/relative seek through `seekPlaybackTo`; MPV writes absolute `time-pos`, while Media3 sets explicit `SeekParameters` and `seekTo` (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerPlaybackEvents.kt:1173-1239`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerMpv.kt:521-557`). Speed routes to MPV `speed` or Media3 `setPlaybackSpeed`; the Media3 audio sink forces encoded passthrough/offload to PCM when speed is not 1× (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerPlaybackEvents.kt:1352-1374`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlaybackSpeedAwareAudioSink.kt:72-130`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlaybackSpeedAwareAudioRenderer.kt:37-62`).

**Evidence.** MPV's official manual confirms speed inserts pitch-preserving tempo correction by default ([mpv speed](https://mpv.io/manual/stable/#options-speed)). For Media3 merging, upstream requires all enabled child periods to seek to exactly the primary's resulting position (`MergingMediaPeriod.java:270-275`); a non-seekable/growing sidecar therefore cannot be assumed to follow arbitrary primary seeks.

**So what.** Introduce a `DubPlaybackCoordinator` at `PlayerRuntimeController.onEvent/seekPlaybackTo/setPlaybackSpeedInternal`, not in Compose. On seek: increment generation, cancel outstanding synthesis/segment fetch, tell producer `targetMediaTimeMs`, mute/fallback to original audio, wait for a new segment covering the target, atomically select dubbed audio, and crossfade. On speed change: transmit speed to the producer or rely on player time-stretch only if the sidecar carries source-media timestamps; disable near-real-time dubbing at reverse/unsupported rates. Use exact media time, never wall clock alone.

### 8. Track state and `AudioSelectionOverlay` need identity/origin/status, not just a flattened index

**What.** `TrackInfo` contains index/name/language/id/codec/channels/selection/sample rate, with no source-engine-independent stable key, external/dubbed flag, readiness, coverage, or error (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerUiState.kt:239-250`). Media3 flattening walks groups in current order, and selection later re-walks them by the same flattened index (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTracks.kt:24-137`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTrackSelection.kt:60-80`). MPV does preserve `trackId` and external status internally, but external is discarded while mapping audio to `TrackInfo` (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:500-580`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerMpv.kt:305-340`).

**Evidence.** Media3 official docs warn that a `TrackSelectionOverride` only applies to an exactly matching `TrackGroup`, so it may not survive a changed item/group ([Track selection overrides](https://developer.android.com/media/media3/exoplayer/track-selection#selecting_specific_tracks)). Nuvio already compensates across engine rebuilds using language/name/track-ID hints (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerEngineFailover.kt:143-258`).

**So what.** Add `origin` (`EMBEDDED`, `MANIFEST_RENDITION`, `DUB_EXTERNAL`), stable `selectionKey`, producer status, available-through media time, and external flag. Keep a dedicated `selectedAudioKey`; retain index only for UI ordering. The overlay should show “Dub — generating / ready to 12:34 / recovering / original fallback”, permit manual original/dub selection, and expose reset delay. During a partial gap do not pretend the dub remains selected and silently emit nothing—show fallback state and record it.

### 9. Engine failover currently preserves ordinary tracks and position, but an external dub would be lost

**What.** Startup/manual failover captures position and a track preference, releases the current engine, initializes the other, and restores by loose track identity (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerEngineFailover.kt:10-62`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerEngineFailover.kt:66-132`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerEngineFailover.kt:143-258`). The capture understands MPV external **subtitles**, but audio capture stores only language/name/ID and no sidecar descriptor (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerEngineFailover.kt:214-258`). Generic errors can retry/rebuild twice; audio failures ladder through PCM, safe-audio and then disabled-audio; startup can switch engines (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerErrorRecovery.kt:30-103`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerErrorRecovery.kt:240-297`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:1412-1483`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:1506-1522`).

**Evidence.** MPV setup re-loads only `currentStreamUrl/currentHeaders` (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerMpv.kt:15-47`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerMpv.kt:93-146`), while Media3 setup creates only the primary source. Rebuilds therefore cannot recreate a sidecar unless it is durable controller session state.

**So what.** Put the dub descriptor/session and desired selection in controller state, not `TrackInfo` or view state. Every initialize/retry/failover must call one idempotent “attach current dub generation” routine. Failover policy should distinguish primary failure from dub-only failure: a 404/timeout/decoder failure on auxiliary audio should fall back to original audio and keep video playing, not consume whole-player engine failover. Standards-native proxy/remux offers the best parity because both engines reopen the same primary URL at the same position.

### 10. Headers, DRM, torrent/local, external players, and cache sharply constrain viable architectures

**Headers.** Media3 creates a header-aware OkHttp `DataSource.Factory`; it also intentionally re-adds Authorization on cross-host redirects (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerPlaybackNetworking.kt:91-132`). This is convenient for a primary WebDAV URL but dangerous if reused for an unrelated dub host. MPV serializes all current headers into global `http-header-fields` (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:656-682`). Use independent headers in direct Media3 merge and credential-free localhost URLs for MPV/proxy. Sanitize CR/LF, commas and hop-by-hop fields, redact values, and key caches by authorization/session.

**DRM.** Nuvio's `MediaItem` builder sets URI/MIME/metadata/subtitles but no `DrmConfiguration` (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:101-115`). Official Media3 requires a DRM UUID and supports license URI, request headers and multi-session in `MediaItem.DrmConfiguration` ([Media items — protected content](https://developer.android.com/media/media3/exoplayer/media-items#protected-content)); Widevine/PlayReady support is format/API constrained ([DRM](https://developer.android.com/media/media3/exoplayer/drm)). The official mpv manual documents no Android Widevine/CDM playback mechanism. Consequently, declare DRM dubbing unsupported until the primary DRM contract is modeled and licensed. Do not decrypt/proxy protected media outside an authorized secure design.

**Torrent/local.** Torrent playback is converted by TorrServer to a localhost HTTP URL with empty headers and normal Range seeking (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerStartup.kt:43-91`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTorrent.kt:15-44`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerTorrent.kt:158-201`). A localhost dubbing proxy can therefore consume the same playback clock without touching torrent pieces. Direct Media3 merge can work with a finalized local/content audio URI because `DefaultDataSource` routes local schemes, but the sidecar must independently seek. Stop the dub producer before `torrentService.stopStream()` on teardown to avoid reads after upstream shutdown.

**External players.** Nuvio hands off only one `ACTION_VIEW` video URI, generic header extras, resume position, and subtitles (`app/src/main/java/com/nuvio/tv/core/player/ExternalPlayerLauncher.kt:12-94`); `PlayerViewModel` stops/releases internal playback immediately before launch (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerViewModel.kt:264-367`). There is no portable Android Intent contract for auxiliary audio or delay. For parity, external players require a single remux/proxy URL containing/advertising the dub; otherwise disable the dub on handoff with a clear warning. Headers are best-effort extras and player-specific.

**Cache/memory/network.** Media3 VOD cache excludes HLS/DASH and appears inert in this tree: `sharedSimpleCache` is read but no assignment exists (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:154-181`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:314-316`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactory.kt:377-392`). MPV explicitly budgets 64 MiB forward plus 64 MiB back demux cache (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:631-632`); official mpv says demuxer limits control readahead/past data and optional disk cache is temporary and deleted on close ([mpv cache](https://mpv.io/manual/stable/#cache)). A second independent audio fetch adds requests, buffers, decoder state and possibly duplicate upstream traffic. A localhost proxy should keep a bounded segment ring (time and bytes), share generated audio across engine reopens, evict before/behind playhead by generation, and report video/audio bytes separately.

### 11. Teardown is comprehensive for current engines but needs a session-level cancellation order

**What.** `releasePlayer` unregisters route callbacks, cancels jobs, releases media session/MPV/ExoPlayer, clears sinks and timeline; controller `onCleared` also stops torrent and shuts down retained parallel sessions (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerLifecycle.kt:7-78`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeController.kt:652-667`). MPV `destroy()` clears load state (`app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt:584-597`). Source switching currently flushes/releases before applying and preparing the new primary (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerStreams.kt:787-867`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerStreams.kt:1324-1437`).

**So what.** Teardown order for dubbing should be: mark generation cancelled; stop accepting producer output; detach/mute external audio; close active response bodies/websocket/process; release player; delete unreferenced temp segments; then stop TorrServer if owned. Use generation tokens in every callback so a late segment from episode A cannot attach to episode B. Do not block main-thread player release on model/network shutdown; bound graceful shutdown and then force-close.

### 12. Diagnostics cover Media3 deeply but are insufficient for dub sync and weak for MPV

**What.** Media3 analytics records decoder initialization/release, selected format, underruns, loads, bandwidth, state, speed, errors, health and raw connection logs (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerInitialization.kt:1568-1768`; `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerPlaybackAnalyticsDiagnostics.kt:480-558`, `app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerPlaybackAnalyticsDiagnostics.kt:641-747`). Issue reports include selected audio label and header **names**, not values (`app/src/main/java/com/nuvio/tv/ui/screens/player/PlayerRuntimeControllerPlaybackEvents.kt:400-443`; `app/src/main/java/com/nuvio/tv/data/repository/PlaybackIssueReportRepository.kt:235-265`). MPV's progress/tracks are polled, but it does not emit equivalent load/decoder/underrun analytics.

**So what.** Add `dub_session_id_hash`, generation, transport, producer/model version, source language/target language, requested/available media-time range, selected dub key, base/user/runtime/effective delay, measured phase error, correction action, correction magnitude, seek-to-first-dub latency, fallback reason/duration, segment sequence/duration/bytes/HTTP status, audio decoder/format, buffer ahead/behind, and external-player compatibility. Never report transcript text, token/header values or full signed URLs. Add MPV property observations/log callbacks if the wrapper permits; otherwise expose explicit session-proxy metrics so both engines share diagnostics.

## Architecture evaluation

| Option | Startup / switching | Seek & partial audio | Sync / correction | Headers / DRM | Engine parity | Memory / network | Verdict |
|---|---|---|---|---|---|---|---|
| **Media3 `MergingMediaSource` + progressive sidecar** | Requires both child timelines/prepare; selecting is native once exposed | Good only if sidecar is finalized and exactly seekable; partial EOS/growing indexes are brittle | Structural PTS alignment; explicit base delay still needed; strict equal child seek results | Independent Media3 data sources possible; DRM must be modeled per source and tested | No direct parity; separate MPV work | Two fetch/buffer pipelines; primary cache currently questionable | **Constrained VOD fallback**, not robust live |
| **HLS alternate audio / DASH AdaptationSet** | Native manifest track discovery; can switch by normal track override | Best direct segmented semantics; seek via manifest window; partial availability explicit | Shared segment timeline; discontinuities/periods are standardized; client delay still available | Media3 supports request headers/DRM when configured; localhost avoids header leakage | MPV understands HLS/DASH broadly; exact Android build must be tested | Segment overhead but bounded; avoid duplicate generation and playlist churn | **Preferred robust transport** |
| **Local remux/proxy to one playable URL** | One URL for both engines/external handoff; startup includes proxy/remux delay | Proxy can map Range/seek and regenerate from target; easiest failover parity | Proxy owns canonical PTS and correction; can crossfade/pad/drop | Keep credentials server-side; DRM generally a blocker; enforce localhost token | **Best parity**, including external players if format accepted | CPU/transmux cost and possible duplicate video bandwidth unless true streaming proxy; bounded ring required | **Preferred platform architecture** |
| **MPV `audio-add`** | Minimal Nuvio changes; hot attach/select; normal `track-list` | MPV manages seek only if external source is seekable; growing remote file remains format-dependent | Native `audio-delay`; mpv's clock/speed machinery is mature | Current wrapper's headers are global; no demonstrated DRM | MPV only unless paired with proxy/Media3 merge | Second demux/cache; Nuvio allocates up to 128 MiB packet cache before decoder memory | **Fastest MVP**, experimental |
| **Raw segmented injection into player internals** | Requires custom MediaSource/SampleStream and an MPV equivalent or localhost demuxer | Must implement discontinuity, EOS, backpressure, random seek, cancellation and generation safety | Full control, but also full clock/sample-format responsibility | Custom encryption/header/security burden | Poor unless the injection is actually a standard localhost stream | Highest code/QA cost and leak risk | **Reject as MVP**; express injection through HLS/DASH/proxy |

## Recommended delivery

### MVP: MPV external audio, finalized/seekable asset only

1. Add `AuxiliaryAudioDescriptor` and session/generation state at the resolved playback/controller boundary; support only clear VOD and one completed progressive audio URI initially.
2. Add `NuvioMpvSurfaceView.audioAdd/audioRemove/audioReload`, invoke official `audio-add ... select`, poll/observe `track-list` until `external=true`, and map it to a stable dubbed `TrackInfo`. Use a localhost tokenized URL so no primary credentials are copied.
3. Reuse `AudioSelectionOverlay`, `OnSetAudioDelayMs`, centralized seek and speed. On every seek, mark dub recovering and fall back to original if the external demuxer cannot cover the target promptly. Keep original audio available for instant rollback.
4. On source/episode switch, retry, failover or release, cancel by generation and remove the external track before destroying MPV. Disable automatic Media3 failover while an MPV-only dub is active, or make failover explicitly drop the dub and notify the user.
5. Clearly scope: no live, DRM, external player, non-seekable sidecar, or guaranteed engine parity. This is an evidence-gathering MVP, not the end architecture.

### Media3 VOD increment: finalized sidecar merge

1. Add `createPlaybackMediaSource(primary, audio)` with independent normalized URLs, headers, MIME hints and load policies.
2. Compose a video/text-filtered primary with an audio-only sidecar via `MergingMediaSource(adjustPeriodTimeOffsets=true, clipDurations=false, ...)`; preserve primary timeline and represent known lead-in with PTS/padding rather than shortest clipping.
3. Wrap delay around the final composite and expose merged sidecar track groups through existing enumeration. Use stable origin-aware selection keys, not flattened index persistence.
4. Gate by preflight: one-period timelines, seekability, duration tolerance, finalized file, supported codec, no unsupported DRM. On auxiliary load/decoder failure, select embedded audio and continue; do not fail the primary.
5. Validate against Nuvio's actual forked AAR. Upstream Media3 1.8.0 fixed a `MergingMediaSource` leak, while the currently documented stable is 1.11.0 ([Media3 release notes](https://developer.android.com/jetpack/androidx/releases/media3#1.8.0)); Nuvio's mixed local binaries need an explicit version/ABI receipt before relying on upstream behavior.

### Robust near-real-time: localhost session proxy with native adaptive audio

1. Create a process-scoped `DubSessionManager` independent of Compose/ViewModel lifetimes. It consumes source media-time events, sends audio/transcript windows to the producer, and receives audio chunks tagged with exact source media times and generation.
2. Publish a tokenized `127.0.0.1` HLS master or DASH MPD containing proxied original video and dubbed audio, or remux to one progressive output where appropriate. Align segment PTS to source media time; pad initial/gap silence; atomically publish only complete segments; preserve old advertised segments for the seek ring.
3. The controller opens one proxy URL in Media3 or MPV. Normal track enumeration, seek, speed, engine failover and external handoff operate on the same transport. If external player cannot reach app localhost/process lifetime reliably, disable that handoff or export a finalized remux.
4. Correction loop: maintain `targetAudioPts = sourcePosition + baseOffset + userDelay`; estimate drift from producer PTS and player/proxy consumption; use bounded tempo correction and crossfaded sample insert/drop; hard-resync on seek/discontinuity/generation change. Keep correction in audio/proxy rather than repeatedly shifting video timestamps.
5. Maintain a bounded time/byte segment ring (for example target back window plus forward window), one synthesis request per source-time range, backpressure, cancellation, and separate metrics. Original audio remains selectable; gaps/timeouts automatically crossfade back rather than stall video.

## Failure modes and required behavior

| Failure | Detection seam | Required behavior |
|---|---|---|
| Sidecar 401/403/404/expired token | Media3 child load event or proxy fetch; MPV/proxy status | Do not retry forever; redact credentials; switch to original audio and keep video; offer regenerate/reauth. |
| Primary headers leak to dubbing host | Request-factory/proxy test | Block cross-origin inherited Authorization/Cookie/Host by default; allow explicit per-audio headers only. |
| Sidecar shorter/partial EOS | coverage metadata, EOS before primary | Never use shortest-duration clipping; crossfade to original/silence and show “generating”; resume at next valid boundary. |
| Sidecar timeline/period mismatch | Media3 preflight / `IllegalMergeException` | Reject merge before playback and use MPV/proxy/original; no whole-player retry loop. |
| Child seek differs from primary | merge exception or post-seek timeout | Abandon direct merge for this asset; reopen proxy at target; original audio during recovery. |
| Seek into unavailable future/past | generation coverage map | Cancel obsolete work, request target window, preserve playback with original audio, attach only matching generation. |
| Track switch hangs/buffers | existing one-ms nudge, timeout around selected-key confirmation | Roll back selection; never repeatedly seek/nudge in a loop. |
| Speed/passthrough failure | existing PCM policy/audio analytics | Force PCM as Nuvio already does; restore original track if dubbed decoder fails. |
| Engine failover | engine-switch seam | Recreate session from descriptor at saved position or explicitly drop dub; never match a new embedded track merely by same language/name. |
| Route change | audio-route callback | Preserve user route delay separately from dub base/correction; reapply after MPV `ao-reload`; do not rebuild video. |
| Producer crash/late callback | generation/session token | Ignore late output, close resources, original-audio fallback, bounded restart. |
| Memory/disk pressure | proxy ring accounting / allocator telemetry | Shrink/evict ring, stop synthesis ahead, never duplicate unbounded segments; do not compete blindly with MPV's 128 MiB demux budget. |
| DRM source | preflight | Fail closed unless licensed Media3 DRM and secure transport are explicitly implemented; no decrypt/remux shortcut. |
| External player handoff | launcher capability policy | Require single muxed/adaptive URL; otherwise explain that dub stays in Nuvio and launch original only after consent. |

## Test seams

### Pure JVM/unit

1. **Descriptor/header policy:** primary and audio URL normalization; URL-userinfo auth; `Range` stripping; no cross-host Authorization/Cookie/Host inheritance; CR/LF rejection; cache/session keys include audio identity but never expose token values. Extend `PlayerMediaSourceFactoryTest` (`app/src/test/java/com/nuvio/tv/ui/screens/player/PlayerMediaSourceFactoryTest.kt:14-170`).
2. **Timeline policy:** one-period finalized accepted; period mismatch, unknown/short duration, live/dynamic, non-seekable and partial sidecar rejected or routed to proxy; positive/negative base offsets and silence-padding calculations.
3. **Clock/correction:** deterministic fake clock for no drift, ±ppm drift, jitter, delayed chunks, speed changes and discontinuities; assert deadband, max tempo, crossfade/hard-resync thresholds and no oscillation.
4. **Generation state machine:** seek/source switch/retry/failover while chunk N is in flight; late callback ignored; only matching-generation coverage may attach/select.
5. **Track identity:** merged Media3 IDs, MPV external IDs, manifest rendition replacement and engine failover restore by stable dub key—not flattened index or language alone.
6. **Delay composition:** `route + base + correction` clamp/sign for both engines; persistence stores only route/user component. Existing MPV conversion/clamp coverage is at `app/src/test/java/com/nuvio/tv/ui/screens/player/BluetoothAudioRoutePolicyTest.kt:162-168`.
7. **Error classification:** auxiliary-only errors choose original fallback and do not consume primary retry/engine-failover budget. Extend the existing audio failure ladder tests (`app/src/test/java/com/nuvio/tv/ui/screens/player/AudioTrackFailureClassificationTest.kt:12-70`).

### Media3 integration (Robolectric/instrumented with fake sources and local HTTP server)

1. Actual Nuvio AAR `MergingMediaSource`: equal/mismatched periods, offset timeline, primary longer/audio shorter with `clipDurations=false`, unknown duration, track-group IDs, source release/weak-reference leak.
2. Seek matrix at 0, middle, near EOS, backward into buffer and outside buffer; assert both child positions or deterministic fallback, no `Children enabled at different positions`/`Unexpected child seekToUs result` crash.
3. HLS/DASH fixtures with original + dubbed audio: chunkless preparation metadata present/missing, alternate language/label, runtime switch, delayed/new segments, discontinuity, sliding window, 404/410/429 and independent headers.
4. Progressive partial fixture: growing Content-Length/chunked response, delayed bytes, range requests, EOS then append; document formats/devices that fail and keep outside support gate.
5. Speed/delay: 0.5×/1×/1.5× with AAC and encoded surround; assert PCM fallback, selected dub persistence, seek and subtitle offset behavior.
6. Teardown/stress: 100 attach/select/seek/remove/rebuild cycles; inspect active calls, allocator, file descriptors, cache files, native memory and weak references.

### MPV device/instrumented

1. Expose a command adapter around `BaseMPVView` so tests can assert exact `audio-add/remove/reload`, `aid`, `audio-delay`, `time-pos`, `speed` and header/property order without a native surface.
2. Device fixtures: local AAC/M4A/Opus, HTTP Range/no-Range, HLS audio-only, growing file, auth failure, malformed timestamps, short audio, and audio decoder failure. Assert `track-list/N/external`, selected ID and playback continuity.
3. Seek/speed/delay matrix and track attach during play/pause/buffer; verify delay remains after seek and `ao-reload` as current code intends.
4. MPV → Media3 → MPV failover at nonzero position; proxy path must preserve dub selection/coverage; direct MPV MVP must explicitly record/drop unsupported parity.
5. Measure total PSS/native heap/network with Nuvio's current 64+64 MiB MPV demux cache and proxy ring; enforce a device-tier budget.

### End-to-end acceptance

- 30/60/120-minute content with scripted seeks, pause/resume, app background, route changes, 0.75×/1×/1.5×, source switch, episode switch and injected producer/network faults.
- Objective sync: known clap/impulse markers at start/middle/end; target median absolute error ≤80 ms and p95 ≤150 ms after settling, no audible hard correction under threshold, recovery to dubbed audio within a product-defined bound after seek.
- Verify original-audio fallback is continuous, UI state truthful, no primary credentials leave intended hosts, no temp/session artifact survives teardown beyond retention policy, and issue reports contain sync metrics but no sensitive content.

## Recommendations

1. **Ship MPV-only finalized-sidecar MVP behind a feature flag** to validate UX, track identity, manual delay, cancellation and telemetry quickly.
2. **In parallel, build the localhost HLS/DASH/remux session proxy as the target**, because it is the only evaluated option that naturally spans Media3, MPV, seeks, partial production, failover and (sometimes) external players.
3. **Add finalized-sidecar Media3 merge only as a strict VOD fallback**, using separate headers, primary audio filtering, `adjustPeriodTimeOffsets=true`, `clipDurations=false`, and deterministic auxiliary-error fallback.
4. **Do not build bespoke raw segmented `SampleStream` injection first.** The strict Media3 multi-child seek contract and lack of an equivalent Nuvio MPV API make it high-risk duplication of an adaptive demuxer.
5. **Model DRM and security before enabling protected streams.** Nuvio's current primary MediaItem does not configure DRM; proxy/remux must fail closed.
6. **Upgrade diagnostics and tests before broad rollout**, especially MPV load/error visibility, phase-error telemetry, generation races, credential boundaries, and long-run memory/network budgets.

## Open questions

1. What exact Media3 commit/API contract produced Nuvio's local AARs? The Gradle comments point to 1.8.0, but binaries were updated independently; publish a build manifest/SBOM and run the merge tests against them.
2. What audio container/codec and delivery behavior does the dubbing producer provide: completed file, append-only byte stream, timestamped chunks, HLS/DASH, or websocket PCM? This determines whether the MPV MVP can use direct `audio-add` or must begin with a proxy.
3. Can the producer regenerate arbitrary media-time windows after seeks, and does every chunk carry authoritative source PTS? Without this, robust arbitrary seeking and drift correction are impossible.
4. Must dubbing work for live TV, DRM, torrents, local/content URIs and external players in the first release, or can support be explicitly tiered? DRM and external-player parity are architecture-changing requirements.
5. What latency, sync-error, recovery-time, CPU/PSS and data-usage budgets apply across target Android TV tiers? These are needed to choose segment duration, ring size and correction thresholds.
6. Does `mpv-android-lib:0.1.12` bundle an mpv version with all documented current commands/properties and per-file option behavior? Verify at runtime (`mpv-version`, command/property list) and pin it in diagnostics.
